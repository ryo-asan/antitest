# Antigravity (AGY) 基本操作・コマンドマニュアル

私は Antigravity (AGY) と呼ばれるエージェント型AIコーディングアシスタントです。ユーザーの皆様のコーディングタスクや各種作業をサポートするため、様々なツールを使用することができます。

## 1. 基本的な使い方
自然言語で指示を出すだけで、私が適切なツールを選択して実行します。（例: 「〜をして」「〜を調べて」）

また、チャットUI上で以下の **スラッシュコマンド** を入力することで、特定の高度なワークフローや専門的なモードを呼び出すことができます。

## 2. 便利なスラッシュコマンド一覧

どのようなタスクを行いたいかに合わせて、以下のコマンドを活用してください。

| コマンド | 用途・できること |
| :--- | :--- |
| `/goal <タスク>` | **自律的な長期タスクの実行**: エラーが起きても自己解決を試み、目標達成まで止まらずに徹底的に作業を継続します。（例: 夜間に大規模なリファクタリングを任せる場合など） |
| `/plan <タスク>` | **複雑なタスクの計画立案**: 実行前にステップバイステップで慎重な計画を立て、方針を明確にしてから作業に入ります。 |
| `/grill-me` | **要件定義のインタビュー**: ユーザーと対話形式で要件や設計方針について質問を繰り返し、不明確な点を解消してから計画を練ります。 |
| `/schedule <タスク>` | **スケジュール・タイマー実行**: 指定時間後のタイマーや、Cron形式での定期実行タスク（監視やリマインダーなど）を設定します。 |
| `/teamwork-preview` | **マルチエージェントでの作業**: 大規模なプロジェクトにおいて、自律的な複数のサブエージェントチームを編成して並行作業を行います。 |
| `/learn` | **学習とカスタマイズ**: ユーザーが手動で修正した手順や複雑な環境構築の手順を学習し、今後のタスクで自律的に再利用できるようにルール化・永続化します。 |
| `/help` | **ヘルプの表示**: 利用可能なスラッシュコマンドや各種操作のヘルプを確認します。 |
| `/exit` (または `/quit`) | **終了**: CLIセッションを終了します。（`Ctrl+D Ctrl+D` でも可能） |

## 3. 私が実行可能な主なアクション

これらのアクションは特別なコマンドは不要で、**チャットで自然な言葉でお願いするだけ**で実行します。必要に応じて適宜ユーザーに確認（Approve）を取りながら進行します。

*   **ファイル・ディレクトリ操作**: ディレクトリ一覧表示、ファイル内容の閲覧、新規ファイルの作成、複数箇所の高度な同時編集。
*   **検索・情報収集**: リポジトリ内の特定の文字列・正規表現の検索（`grep`）、Web検索、指定URLからのコンテンツ（Markdown）読み込み。
*   **システムコマンド実行**: Linux環境（bash）でのコマンド実行（ビルド、テスト、環境構築など）。永続的なターミナルセッションを維持して環境変数を共有することも可能です。
*   **タスク・エージェント管理**: リサーチ等の専用サブエージェントの起動、バックグラウンドタスクの実行と管理。
*   **デザインとUI・画像生成**: テキストプロンプトからの画像生成、既存画像の編集、UIモックアップの作成。
*   **アーティファクトの生成**: 複雑なレポート、表、ダイアグラム、コードの差分などを、見やすいMarkdownドキュメント（アーティファクト）として生成・提示。

## 4. AIの種類（モデル）の指定

タスクの難易度や用途に合わせて、AIのモデルを変更することができます。指定には以下のコマンドや設定を利用します。

*   **CLI起動時のコマンド**: `agy --model <モデル名>` として起動することで、特定のモデルを利用できます。（例: `agy --model gemini-1.5-pro`）
    *   *※利用可能なモデル一覧は `agy models` コマンドで確認できます。以下は指定可能なモデルの例です。*
        ```text
        gemini-3.6-flash-high     Gemini 3.6 Flash (High)
        gemini-3.6-flash-medium   Gemini 3.6 Flash (Medium)
        gemini-3.6-flash-low      Gemini 3.6 Flash (Low)
        gemini-3.5-flash-high     Gemini 3.5 Flash (High)
        gemini-3.5-flash-medium   Gemini 3.5 Flash (Medium)
        gemini-3.5-flash-low      Gemini 3.5 Flash (Low)
        gemini-3.1-pro-high       Gemini 3.1 Pro (High)
        gemini-3.1-pro-low        Gemini 3.1 Pro (Low)
        claude-sonnet-4-6         Claude Sonnet 4.6 (Thinking)
        claude-opus-4-6-thinking  Claude Opus 4.6 (Thinking)
        gpt-oss-120b-medium       GPT-OSS 120B (Medium)
        ```
*   **チャット上のスラッシュコマンド**: チャット中に `/model <モデル名>` と入力することで、会話の途中でモデルを切り替えることができます。
*   **全体の設定を変更する**: アプリケーション・CLIのユーザー設定メニュー（`Model Selection`）から、標準で利用するモデルを切り替えることができます。
*   **サブエージェントの使い分け**: 私が複雑なタスクを分担させるためサブエージェントを起動する際、タスクに応じて以下のモデルを使い分けます（ユーザーから「〜のモデルで実行して」と直接指定することも可能です）。
    *   `pro`: 複雑な推論、大規模なリファクタリング、多段階の計画向けの大規模モデル。
    *   `flash`: 情報の検索やファイル読み取りなどのシンプルなタスクを高速にこなすモデル。
    *   `flash_lite`: さらに軽量で高速なモデル。

## 5. AIへのルール・設定のカスタマイズ（Rules）

特定のコーディング規約、プロジェクト固有のルール、よく使う手順などを設定ファイルとして定義しておくと、私が自動的にそれを読み込み、ルールに従って作業を行います。

### 📌 ルール（Rules）の定義方法
Markdownファイル（`.md`）を作成して特定の場所に配置するだけで、自動的にルールとして認識されます。

*   **プロジェクト単位のルール (Workspace Rules)**
    *   ワークスペース（プロジェクト）のルートディレクトリに `GEMINI.md` または `AGENTS.md` というファイルを配置する。
    *   または、ルートに `.agents/rules/` ディレクトリを作成し、その中に任意の `.md` ファイルを配置する。
*   **グローバルなルール (Global Rules)**
    *   すべてのプロジェクトで共通して適用したいルールは、`~/.gemini/config/rules/` ディレクトリ内に `.md` ファイルを配置する。

**【活用例】**
「コードを書くときは必ずTypeScriptを使用し、変数名はキャメルケースにする」「単体テストにはJestを使う」などの指示を `GEMINI.md` に記載しておけば、毎回チャットで指示しなくても、私が自動的にそのルールを遵守してコードを生成・修正します。
